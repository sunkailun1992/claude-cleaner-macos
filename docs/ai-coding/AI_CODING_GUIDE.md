# AI 编码指南

入口为根目录 [AGENTS.md](../../AGENTS.md)。本页说明如何推进已授权任务；路径/执行细则见 [工程护栏](ENGINEERING_GUARDRAILS.md)，数据与权限边界见 [安全编码规范](SECURITY_CODING_SPEC.md)，证据要求见 [测试规范](TESTING_SPEC.md)。

## 开始工作

1. 先确认用户要的是调研、比较、修复还是执行。咨询不自动扩大为实施；明确授权的任务持续完成，不反复请求相同许可。
2. 查看当前分支、状态、相关实现与已有测试，识别并行工作和未提交变更。只改本任务文件，不清理其他人的改动。
3. 处理删除范围或残留问题时，先读 [coverage.md](../coverage.md)、[sources.md](../sources.md)，区分官方事实、公开报告和本项目保守决策。
4. 把问题落实为一个可核验的行为：什么合成目录、安装渠道或系统命令会触发错误，正确输出/保留/退出码是什么。不要先叠加猜测性补丁。

## 实现与纠偏

修复用最小必要改动，沿 Planner → 系统动作/Remover → Auditor → CLI 报告检查影响。新增自动删除目标需要证据、归属规则、保护边界和能捕捉误删的回归夹具；仅增加同名路径列表不足以成立。

安全边界与执行策略是产品行为。变更默认选项、确认短语、人工残留语义、退出码或共享目录保护时，同步测试、帮助、README 和覆盖说明。不要让文档先声称未实现的能力。

第一次修复未捕捉原症状时，更新假设并收集更有区分力的证据；不要沿相同猜测扩大删除。无法安全判定归属时改为保留/人工项，并说明何种证据可以重新纳入。

## 验证和交付

运行 `bash scripts/check.sh`；必要的目标测试用于定位，但不能替代提交前完整检查。真实盘点只读，真实卸载不因“写清理器”而自动获得授权。不要为验证执行用户应用、凭据 helper、未知 shell 配置或第三方安装器。

完成说明包括：最终改动与目的、实际验证结果、仍需人工处理的内容、未做的实机/账号验收及相关文件。源码完成、本地检查、CI、实际删除和用户验收分别报告，不用后一个阶段的措辞描述前一个阶段。

不要保存私人扫描输出作为开源证据。测试使用合成路径与数据；公开说明保留必要复现信息即可。提交、推送和合并按 [MAINTAINERS.md](../../MAINTAINERS.md) 执行，不擅自改仓库权限。
