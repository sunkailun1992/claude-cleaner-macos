# macOS Claude 清理器设计

## 目标与授权

开源、无第三方运行依赖的 macOS 脚本，清理当前用户的 Claude Desktop、Claude Code 和已知专属残留。用户明确要求编写、创建公开 GitHub 仓库并提交推送；确认默认清理用户环境，项目文件单独选项。本轮开发不对开发者真实环境执行删除。

## 方案

采用 macOS 自带 Bash 3.2 启动器与系统 Ruby 2.6+ 标准库。纯 Shell 很难可靠表达结构化计划和链接边界；Python 3 并非所有新装 macOS 自带，因此采用 Ruby。默认只预览，双击入口展示计划再确认。`--apply --yes` 是显式无人值守入口。固定清单、动态盘点、删除后重新盘点；失败与未覆盖范围不得输出成全部成功。

## 模块

- `planner.rb`：只读枚举已知路径；可注入路径根以对临时夹具测试。拒绝跨越符号链接父目录；叶子链接仅删除链接。保护 `~/.claude/security`（其他工具可能共用）和项目 `worktrees`。
- `remover.rb`：只接受 Planner 生成的目标；执行前重新检查路径身份、父路径链接、受保护范围；权限或竞态问题计入失败。不跟随目录中的链接，不递归扫描整个磁盘。
- `system.rb`：以 argv 调用固定系统命令，盘点并卸载实际安装的 Homebrew/npm 包，检查特定 Claude 进程、用户级 launchd 和精确钥匙串服务。不读取密码、token 或会话内容；不改设备标识、代理、信任或系统安全策略。
- CLI：预览/执行/验证，JSON 报告，当前用户 home、当前用户 Darwin runtime，明确限定的项目选项；拒绝作为 root 运行。系统权限不足如实报告。浏览器站点数据只给人工步骤，绝不删整个共享浏览器数据库。

## 范围

Desktop 主版及独立第三方版数据、常见安装渠道、用户配置及备份、缓存/日志/偏好/HTTPStorages/状态、已知官方 IDE 扩展专属目录和桥接清单、已知切换器用户数据、当前用户系统缓存。自定义配置目录需要明确限定和安全校验。Cowork 用户产物默认保留，单独选项。项目 `.claude` 和 `CLAUDE.md` 单独 opt-in；Git worktree 不作普通缓存删除。

不承诺取证级擦除：浏览器网站记录、云端账户、Time Machine/APFS 快照、其他用户、未知版本/第三方软件路径与共享依赖另列。没有检测到残留只表示已知清单通过。

## 验收

临时目录覆盖预览无写入、真实删除、幂等、空格/中文路径、叶子链接/父链接、变更后路径、共享安全目录、项目 worktree、权限失败、危险配置路径、失败退出码。系统命令用注入适配器检查精确参数；不执行真实卸载。macOS CI 跑系统 Ruby，Linux CI 跑跨平台核心测试；检查公开内容不含本机私人绝对路径或凭据。

## 贡献治理

维护者和使用其管理员账号的获授权 AI 可直推 main，仍须本地检查及推送后 CI。外部贡献走 PR，由维护者或其授权 AI 审核代码后合并。GitHub 同账号不能给自己的 PR 正式批准：授权 AI 审查外部 PR 后，以管理员身份合并并记录审核证据。main 禁止强推与删除的规则独立、无绕过；PR/检查规则允许管理员始终绕过。仅 squash 合并 PR。
